# 推荐配置管理平台 · 前端开发规范与 AI 协同规则

## 一、 项目定位与目标
- 本项目为“推荐业务配置管理”的 **MVP（最小可行性产品）** 模块，旨在快速验证“Schema 驱动”与“复杂业务表单联动”的前端架构方案。
- AI 角色：作为资深前端搭档，需严格遵守以下工程规范，输出**高可读性、高内聚、低耦合**的代码。
- 所有代码需具备良好的可维护性，核心逻辑需附带注释说明。

## 二、 技术栈与代码规范
- 框架：Vue 3 + `<script setup lang="ts">` + Vite。
- 状态管理：Pinia（严禁在组件内直接解构 store，必须使用 `storeToRefs`）。
- UI 库：Element Plus。
- 命名规范：组件使用 PascalCase（如 `ConfigTable.vue`），组合式函数使用 `useXxx` 前缀。
- 路由与入口：严禁未经授权修改 `src/router/index.ts` 和 `src/main.ts`。
- 列表渲染：`:key` 必须使用稳定的唯一标识（如 `id`），**严禁使用 index 作为 key**。

## 三、 业务逻辑边界与性能约束
1. **列表状态局部更新**：在“生效/下线”切换场景中，必须实现**行级精确更新**。根据行 ID 更新本地状态变量，严禁触发全表网络重载或全量重渲染。
2. **表单字段精确联动**：配置表单存在多态联动（如“人工推荐”显示商品 ID 列表，“算法推荐”显示模型选择）。必须使用 `watch` 精确监听特定字段（如 `() => form.strategyType`），**严禁直接监听整个 `reactive` 表单对象**，避免引发无效的联动计算。
3. **接口交互设计**：需配合 Axios 封装，模拟前后端联调流程；针对状态切换，需采用**乐观更新（Optimistic UI）**策略，并在接口异常时做好状态回滚处理。

## 四、 开发禁令
- 严禁引入未声明的第三方依赖。
- 严禁生成过度设计（如高阶组件、冗余的 Mixin）。
- 每次生成代码后，必须用简短的语言说明实现思路，确保代码可被人工审查（Code Review）。
